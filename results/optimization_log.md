## 第 1 轮：数据预处理 / 噪声清洗

**日期**：2026-06-10  
**优化方向**：预处理（Preprocessing）  
**对照基线**：第 0 轮（未清洗数据 + BiLSTM 注意力 + 类别加权 + 早停），测试集结果如下：

| 指标 | 基线（未清洗） |
|------|----------------|
| 准确率 | 67.13% |
| macro-F1 | 0.5578 |
| 积极 F1 / 召回 | 0.7252 / 71.0% |
| 中性 F1 / 召回 | 0.2148 / 30.9% |
| 消极 F1 / 召回 | 0.7334 / 69.3% |

---

### 1. 优化目标

去除微博文本中与情感无关的噪声，使 `pad_size=30` 的字符窗口尽量保留情感内容，缓解：

- `@用户名` 占用有效长度
- `//@转发链` 引入他人文本
- `[哈哈]` 等表情标签占字符但不直接表达情感
- `http://`、`t.cn/` 链接噪声

---

### 2. 改动内容

**新增文件**

| 文件 | 说明 |
|------|------|
| `preprocess.py` | 清洗函数 `clean_weibo_text()`、统计函数、生成清洗集 |
| `data/weibo_3class_clean.csv` | 清洗后数据集（109,976 条） |
| `results/preprocess_stats.json` | 清洗前后统计（机器可读） |

**清洗规则（按顺序执行）**

1. 去除 URL（`http://`、`t.cn/`）
2. 去除 `回复@xxx:` 前缀
3. 去除 `//@用户名:` 转发链
4. 去除 `@用户名`
5. 去除 `[表情标签]`（如 `[哈哈]`、`[嘻嘻]`）
6. 去除 `#话题#` 外壳，保留话题文字
7. 去除空白字符
8. 清洗后有效长度 < 2 字的样本丢弃

**代码接入**

- `main.py`：训练读取 `weibo_3class_clean.csv`，`load_dataset` 中二次调用清洗
- `test.py`：推理时对输入句子同步清洗，保证训练/推理一致

---

### 3. 清洗效果（数据层面）

| 统计项 | 清洗前 | 清洗后 | 变化 |
|--------|--------|--------|------|
| 样本总数 | 112,743 | 109,976 | -2,767（过短丢弃） |
| 含 `@` 比例 | 58.0% | **1.1%** | ↓ 显著 |
| 含 `[表情]` 比例 | 100% | **0%** | ↓ 全部去除 |
| 含转发 `//@` 比例 | 46.9% | **0.06%** | ↓ 显著 |
| 含链接比例 | 4.7% | **0%** | ↓ 全部去除 |
| 平均文本长度 | 66.0 字 | **40.2 字** | ↓ 噪声去除后更短 |

类别分布变化较小（中性占比仍约 7.8%）。

---

### 4. 模型训练结果对比

训练配置与基线一致（BiLSTM+注意力、类别加权、加权采样、早停、推理校准）。  
训练耗时：约 9 分钟（早停第 11 轮左右）。

---

### 6. 结论

| 维度 | 是否有效果 | 说明 |
|------|------------|------|
| 数据质量 | **有效** | `@`、转发、表情、链接噪声显著减少，有效情感字符占比提高 |
| 中性召回 | **有效** | 测试集召回 30.9% → 44.5%（+13.6 pp） |
| 整体准确率 | **负面** | 67.1% → 58.2%，下降约 9 pp |
| 积极/消极 F1 | **负面** | 微博数据中 `[哈哈]` 等表情是强情感信号，去除后模型失去部分判别依据 |

**本轮总结**：预处理 alone 是**有得有失**——中性识别能力（召回）提升，但整体准确率下降。说明微博原始标签与表情符号高度相关，不能只做「全删」清洗，需要与**中性样本补强**或**保留部分情感表情**等策略配合。

## 第 2 轮：中性样本补充 + 标签感知表情保留 + 三类均衡

**日期**：2026-06-10  
**优化方向**：预处理（A+B 结合）+ 数据均衡  
**对照基线**：第 1 轮（全删表情清洗后）测试集结果

| 指标 | 第 1 轮（全删表情） |
|------|---------------------|
| 准确率 | 58.15% |
| macro-F1 | 0.5058 |
| 积极 F1 / 召回 | 0.6758 / 61.7% |
| 中性 F1 / 召回 | 0.2146 / 44.5% |
| 消极 F1 / 召回 | 0.6269 / 56.7% |

---

### 1. 优化目标

结合用户选定方向：

- **A**：补充中性样本，缓解中性仅 7.8% 的问题
- **B**：保留与标签情感**一致**的微博表情（如积极保留 `[哈哈]`，消极保留 `[怒]`），删除**不一致**表情，避免噪声干扰
- 若积极/消极与中性数量差距过大，**下采样**积极/消极，使三类数量基本一致

---

### 2. 改动内容

**核心文件**：`preprocess.py` → 新增 `build_balanced_dataset()`

| 步骤 | 说明 |
|------|------|
| 标签感知清洗 | 去 `@/转发/链接`；积极仅留 POSITIVE_EMOJI，消极仅留 NEGATIVE_EMOJI，中性仅留 NEUTRAL_EMOJI |
| 中性补充 | 程序化生成 6,000 条中性陈述句（`generate_neutral_samples`） |
| 下采样 | 积极 54,748 → 14,644；消极 49,133 → 14,644；中性 8,644 + 6,000 → 14,644 |
| 输出 | `data/weibo_3class_balanced.csv`（43,932 条，三类 1:1:1） |

**表情处理统计**（清洗阶段）：

- 保留与标签一致表情：**181,831** 个
- 删除不一致表情：**75,920** 个
- 清洗后约 **67.9%** 样本仍含表情（作为情感特征）

**代码接入**：

- `main.py` 改为读取 `weibo_3class_balanced.csv`
- `test.py` 推理时使用 `clean_weibo_text(text, label=None)`，保留全部已知情感表情

### 6. 结论

| 维度 | 是否有效果 | 说明 |
|------|------------|------|
| 三类均衡 | **有效** | 1:1:1 分布，训练更稳定 |

## 附录：架构上限与预训练模型选型参考

### 当前架构（BiLSTM + 注意力 + 腾讯词向量 + 词典加权）的理论上限

| 评估场景 | 预期上限 | 当前位置 |
|----------|----------|----------|
| 均衡下采样测试集（本项目） | **约 83%～86%** | **85.86%**（已接近上限） |
| 原始分布未下采样数据 | 约 78%～82% | 尚未实测 |
| 含反讽/表情不一致的真实微博 | 约 75%～80% | 部分 case 仍难 |

继续在本架构上微调（词典、样本、校准）预计还能提升 **0.5%～1.5%**，边际收益递减。

---

### 换预训练模型的主要选择

| 方案 | 预期准确率（本项目量级） | 开发工作量 | 调试/训练时间 | 部署成本 |
|------|-------------------------|------------|---------------|----------|
| **保持现状 + 集成 2 模型** | 86%～87% | 低（1 天） | CPU 训练 +2h | 低 |
| **TextCNN + BiLSTM 混合** | 84%～87% | 低（1～2 天） | GPU 可选，+0.5 天 | 低 |
| **MacBERT-base 微调** | **88%～92%** | 中（3～5 天） | GPU 4～8h/轮，调参 1～2 天 | 中（需 transformers） |
| **RoBERTa-wwm-ext / ERNIE-3.0-base** | **88%～93%** | 中（3～5 天） | 同 MacBERT | 中 |
| **DeBERTa-v3-large 中文** | **90%～94%** | 高（5～7 天） | GPU 8～16h/轮，显存 ≥8GB | 高（推理慢） |
| **GPT 类生成式 zero-shot** | 不稳定 70%～85% | 低 | 推理贵 | 高 |

**建议路径**：
- 若目标 **86%～87%**：可在当前架构做模型集成或原始分布评估，成本低。
- 若目标 **90%+**：应迁移到 **MacBERT / ERNIE** 微调，一次性重构数据管道与训练脚本（约 3～5 天），收益最大。
